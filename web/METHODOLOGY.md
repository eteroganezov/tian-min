# Метод обработки места и времени

Текущая версия использует зафиксированный метод `TRUE_SOLAR_TIME_V1`.

## Цепочка расчёта

1. Пользователь вводит местную григорианскую дату, местное время и выбирает город из подсказок.
2. `LocationProvider` получает из локального набора данных координаты и IANA time zone выбранного города. Первый похожий город никогда не выбирается автоматически.
3. `civil-time.cjs` по исторической базе IANA определяет абсолютный UTC instant, полный исторический UTC offset и standard offset без DST. Несуществующее время отклоняется, а при повторяющемся времени пользователь должен выбрать первый или второй вариант.
4. `true-solar-time.cjs` вычисляет longitude correction как `4 × (longitude − standard meridian longitude)` минут, Equation of Time по минутной аппроксимации NOAA и отдельно удаляет DST.
5. Полученное true solar local date/time передаётся существующему движку для локальных частей карты: дневного и часового столпов BaZi, даты и часа Zi Wei.
6. Границы 节气 сравниваются как абсолютные моменты. Для совместимости со шкалой `lunar-typescript` UTC instant представляется в `UTC+8`; longitude correction к самому моменту 节气 не применяется.

Ядро принимает время с точностью до минуты, поэтому итоговое истинное солнечное время округляется до ближайшей минуты. Метод и все поправки возвращаются в metadata; скрытый audit trail доступен только в локальной не-production среде при `audit: true`.

## Данные и зависимости

- `city-timezones 1.3.4` — локальный поиск города, координат и IANA time zone; пакет заявлен под MIT.
- `timezonecomplete 5.15.1` + `tzdata` — исторические правила IANA и отдельный standard offset; пакеты заявлены под MIT.
- Внешние API, API keys, rate limits и платные сервисы не используются.

Перед коммерческим выпуском нужно отдельно подтвердить юридическое происхождение именно встроенного набора координат `city-timezones`: пакет маркирован MIT, но его README не указывает первичный источник геоданных и отдельные условия этого источника.

## Ограничения и внешняя верификация

- Поддерживается диапазон 1900–2100 и только локальная григорианская дата.
- Точность координат ограничена координатами города, а не точным адресом роддома.
- Автоматические тесты проверяют часовую механику, DST, переход даты, инварианты карты и сохранение legacy-результатов. Точные астрологические эталоны нового режима должны быть независимо подтверждены профильным специалистом; соответствующий тест явно оставлен `skip`, а не подогнан под предположение.
